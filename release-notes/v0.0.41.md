0.0.41 is on npm under the `next` tag, as 0.0.40 was: `npm install -g @agentorg/cli@next`. `latest` stays 0.0.15. It pins AgentComputer 0.0.41, as 0.0.40 did.

## What you meet

- **`agentorg update` follows the channel you installed from.** Before, it always followed `next`.
  - The install line records its channel, `latest` or `next`, in `~/.agentorg/channel`. `agentorg update` follows it, and so does the GitHub line when run again.
  - **Which channel it records:** the one named, with `--channel` or `AGENTORG_CHANNEL`; else the one already recorded; else `next`, where the line installed AgentOrg before 0.0.41; else `latest`.
  - **So the install page's bare line follows `latest`.** The page serves one release's script on both channels, so its line for `next` names the channel: `curl -fsSL https://<the page>/next/install.sh | AGENTORG_CHANNEL=next bash`.
  - **The GitHub line**, `get.sh`, takes the channel named, else the one recorded, else `next`, as before.
  - **An install the line made before 0.0.41** has no record, and is taken as `next`, which every line until now installed. `agentorg update` follows `next`, and the update records it.
  - `agentorg update` first says which channel it checks: "Checking for updates on AgentOrg's next channel...".
- **`agentorg status` says when a newer release is out** on that channel, in one line with its notes: "Update available: <this version> → <the newer one>. Run agentorg update. Release notes: <its release page>". Nothing updates by itself.
- **`agentorg update --back [--yes]` puts back the release before the last update**, with the home as it was just before that update.
  - **Everything changed since that update is lost:** chats, agents and settings made or changed after it. The command says so, with the release it puts back, and asks "Go back? [y/N]" before it changes anything. Without a terminal, it changes nothing unless given `--yes`.
  - **One step only.** An update keeps that step in `~/.agentorg/previous`, and the next update replaces it. Going forward again is an update.
  - If the release before doesn't answer, what ran is put back.
  - **It goes back only over an update to 0.0.41 or later.** A release's install script keeps the step when it updates to that release, and those before 0.0.41 kept none. So the update from 0.0.40 to 0.0.41 can be undone, and 0.0.40 itself has no `--back`.

## What AgentOrg asks the network, and when

- **`agentorg status`** asks registry.npmjs.org for the recorded channel's version, at most once a day, and only on a Mac where the install line put AgentOrg. It waits 5 seconds at most. A read that fails counts as that day's, so an offline Mac isn't asked again at every `status`.
- **`agentorg update`** asks registry.npmjs.org for the channel's version, and github.com for that release's `install.sh` and `SHA256SUMS`, each time it is run. The release's install script then installs its core from npm, downloads its Mac app from GitHub, and downloads Node from nodejs.org where the release pins a Node not installed yet.
- **`agentorg update --back`** asks github.com for the running release's `install.sh` and `SHA256SUMS`, and downloads nothing else.
- **Running the agent asks nothing.**
- **What a request says.** Each request `agentorg status` and `agentorg update` make is a plain GET, whose only header of AgentOrg's own is `user-agent: agentorg/<version>`. Nothing names you, the home or the install. GitHub serves a release's files from release-assets.githubusercontent.com. The install script downloads with curl and npm, as before.
- **The answer is kept** in `~/.agentorg/update.json`: the channel, the version and notes page last read, and when it asked. `agentorg uninstall` removes it, with the channel and the step back.

## For development

- **The conversation runner's `--long`** plays one long conversation, half a year of support-ticket work, through several compactions.
  - It records each request's tokens, cache share and seconds, and what each compaction's summary requests were given and wrote.
  - After each compaction, it checks the thread held, with one question only the summary can answer.
  - `--stop-on-lost` ends a run whose checks didn't hold, and `--shots DIR` keeps screenshots. None of it runs in CI.
- **The release's Mac check** also checks the channel a fresh install records. It goes back after the update and updates again, and checks that `agentorg uninstall` removes the record and the step.

## What you need to do

- **A home from 0.0.40:** nothing. This release changes nothing a home keeps.
- **A home from 0.0.39 or earlier:** as when 0.0.40 opened such a home.
- **Going back to 0.0.40 with npm** keeps the home as it is, since this release writes nothing new to it. That is from the code, not run.
- **The install line** still installs nothing while no signed Mac app is published, and `agentorg update` stops the same way.
