0.0.39 is on npm under the `next` tag, as 0.0.38 was: `npm install -g @agentorg/cli@next`. `latest` stays 0.0.15. It pins AgentComputer 0.0.41, as 0.0.38 did.

## What you meet

- **Nothing new on the page.** Setup, Team and the conversations look and work as in 0.0.38.
- **An agent with control can turn memory on for itself.** Every agent with an AgentOrg control unit holds control, whatever its Agents setting. That includes the Assistant your home made at its first start.
  - **Asked to remember things from now on,** it looks at what it can add, adds memory to itself and tells you so. Memory works from your next message: a line said in the same message isn't kept yet.
  - **It can take memory off itself again.** Its lines stay, and come back when memory is added again. It can also add memory or control to the agents it made, or take them off.
  - **Each turn it is told what it can add, in a short list,** with what it already holds marked, its own control included. An agent without control is told nothing of it.
  - **The page doesn't show what an agent added,** and can't take it off. The agent, or a program, can.
  - **An agent made later from the Assistant template doesn't hold control.** It is told and offered exactly what 0.0.38 told and offered it.
  - **Measured** on the conversation set, two runs each way, against a build partway through this release, before control was given:
    - Right answers were 14 in three runs and 13 in the fourth, with 10 more in each left for a person to read. The one miss: "Hi!" was answered with the same words as in the runs that passed, but shown after 6.7 seconds, against a limit of 4.
    - Requests on the first twenty conversations were 86 and 85, against 79 and 86. 0.0.38's own runs ranged from 81 to 89.
    - The share of input read from the model's cache was 21.0% and 19.0%, against 23.0% and 26.3%. 0.0.38's own runs ranged from 17.8% to 25.9%.
    - The set's agents hold no control, so these runs show the rest of the release.
    - Told "Remember things for me from now on.", an agent with a computer, the web and control added memory to itself in each of eight runs, two of them on this release's code. Its control was added by the test, not through a control unit.
    - Holding control adds no wait before an answer. From your message to the agent's first request, "Hi!" took 0.84 and 0.61 seconds as the first message after the app started, which costs about 0.6 seconds with or without control. "Thanks!" after it took 0.03 seconds.

## Built, and not yet met

- **Adding a capability to a running agent.** Management now does it, where 0.0.38 refused. A program you run, or another program on the Hub, can add memory or control to a running agent and take it off, with no restart. Management checks nothing about who adds what; the control capability keeps an agent to itself and the agents it made. The page can't add one yet.
- **What an agent is made of, as one tree.** An agent says everything it holds: what every agent has, what its settings name, what was added, each plugin a capability loaded, and what each part added to its latest request. Management's `get` gives that tree while the agent can be asked, and an agent with control reads the same one.
- **An agent's parts as capabilities.** Its instructions, skills, connections, model, store, tools and prompt are now capabilities inside it. The program that runs it reads the tree of what is mounted on it.

## For development
