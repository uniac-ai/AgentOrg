0.0.38 is on npm under the `next` tag, as 0.0.37 was: `npm install -g @agentorg/cli@next`. `latest` stays 0.0.15. It pins AgentComputer 0.0.41, as 0.0.37 did.

## What you meet

- **Each conversation is the agent itself, doing the work.** Before, a front desk read your message and handed the work to a separate worker. Now the agent you talk to does the work in that conversation, with every tool it has, and answers you there.
  - **A question before guessing.** A request it could read more than one way, with nothing said before it to settle which, gets one short question back before any work.
  - **It sees the whole conversation.** It reads every message and reply said there, including those an earlier version's worker answered, so it can tell you what was said before.
  - **One thing at a time in a conversation.** A second request said while it works is read at its next step and done after or with the first; nothing runs side by side inside one conversation.
  - **A busy agent can make a conversation wait.** Each conversation that works takes one of the agent's places, as work did. With four conversations working at once, a fifth waits its turn, even for a quick question.
  - **"Stop that."** Said while one of its commands runs, that command ends, and the agent reads your message and answers it. Said while it is writing, it reads it at its next step, after anything that response started.
  - **"Thanks!" is as quick as before.** It still gets its emoji, and the typing sign goes when the emoji shows.
  - **Activity** lists the conversation as "This conversation", with its calls and steps, and no separate pieces of work.
  - **Measured** on the conversation set, two runs each way: no wrong answers in either run after, against one in each before. Requests on the first twenty conversations were 82 and 76, against 82 and 85; all requests 113 and 108, against 101 and 103.
- **An agent that can't load one of its plugins keeps running without it,** instead of going down. Its line on its page and its row in Team says which plugin and why, in red. It tries again at its next step, or when its settings change. Only an agent that holds a plugin meets this; the page can't add one yet.
- **Memory keeps "Call me Sam."** An agent with memory is told what its lines are for: keep what you would otherwise have to tell it twice, never keep passwords or what you asked it to forget, and don't share your lines in anyone else's conversation. Memory still can't be added from the page: an agent has it only through a stack, a template or a unit change that names it.

## Built, and not yet met

- **Mounting a capability on a running agent.** The contracts for it are in: `capability.provider@1`, and `agents@1`'s `mount`, `unmount` and tree. Nothing calls them yet; management refuses both until a later version.
- **Routing to separate workers** stays in the code, used by nothing. A fault in it that could make a turn repeat without end is fixed.

## What you need to do

- **A home from 0.0.37:** nothing. In a conversation where work was in progress, that work carries on once and answers there; after that, the conversation's agent does the work itself and the old work is given nothing new. Going back to 0.0.37 hasn't been checked.
- **A home from 0.0.36 or earlier:** as when 0.0.37 opened such a home.
- **The install line** still installs nothing while no signed Mac app is published.

## Not run on a Mac

As before, the service under the real launchd, the install line, `agentorg update` and `agentorg uninstall` were checked with stand-ins. "Stop that." during a running command is shown by tests that hold a command open, not in the measured runs, where commands end before the stop is said. No test starts from a 0.0.37 home with work cut off: such work is carried on the way any cut-off turn is.
